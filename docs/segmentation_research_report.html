分割算法优化调研报告

交互式前景分割工作流的简化与重构方案

🔍 现状分析

当前代码中存在 两套独立的分割显示组件（InteractiveImageDisplay 和 IterativeGrabCutDisplay），它们共享大量重复逻辑（坐标映射、缩放、鼠标事件处理），却通过 pack_forget() / pack() 来回切换，不仅造成视觉闪烁，也增加了维护负担。

现存问题

  • 流程过长 完成一次分割需要 6~10 次点击操作：绘制矩形 → 第一次分割 → 切换前景/背景模式 → 涂抹 → 迭代分割 → 应用结果，对拼豆图纸这类粗略分割任务过度设计
  • GMM 模型丢失 segmentation.py 中的 grabcut_interactive() 每次调用都重新创建 bgdModel / fgdModel，丢弃了前序迭代中学习的颜色分布
  • 无背景标记 InteractiveImageDisplay 只能标记前景，mask 中缺少 GC_BGD 样本时 OpenCV 内部 GMM 初始化会因断言 !bgdSamples.empty() && !fgdSamples.empty() 失败
  • 结果显示脱节 分割结果显示在 igc 小部件，实际使用却在 seg_display 通过"应用Mask"按钮，用户需要手动切换下拉菜单查看结果

📚 技术调研

方案 A：OpenCV GrabCut（CPU 原生，推荐）

GrabCut 是基于图割（Graph Cut）的迭代分割算法，内置于 OpenCV 中，无需额外依赖。对于拼豆图画这种不需要像素级精度的场景，3~5 次迭代即可在 CPU 上 100~300ms 完成。

  • GC_INIT_WITH_RECT — 用户绘制矩形框选前景，矩形外标记为确定背景，矩形内标记为可能前景/背景
  • GC_INIT_WITH_MASK — 用户添加前景/背景笔触（硬标签），结合复用 GMM 模型做迭代优化
  • bgdModel(1×65) — 背景高斯混合模型参数，必须在迭代之间保持引用

方案 B：SLIC 超像素 + GrabCut（快速）

cv2.ximgproc.createSuperpixelSLIC() 可将图像分割为 ~1000 个超像素（region），然后在超像素级别运行 GrabCut，将像素级的 O(n) 降为超像素级的 O(s)。对于拼豆的大图（>1500px）有价值，但通常预处理缩放后已低于 1000px，收益有限。

方案 C：轻量级 SAM（MobileSAM / TinySAM）

截至 2026 年，MobileSAMv2 (~56MB)、TinySAM int8 (~30MB) 可在 CPU 上 200~500ms 完成点提示分割。但在拼豆场景下 大材小用：

  • 额外引入 ~30-70MB ONNX 运行时，增加打包体积
  • 拼豆图案最终会量化为 50~200 个色块，GrabCut 的精度已足够
✓ 推荐方案 A — 纯 OpenCV GrabCut，双阶段流程（矩形初始化 + 笔触细化），迭代保留 GMM 模型，3+2 次迭代。

关键优化点

  1. 统一显示组件 — 合并 InteractiveImageDisplay 和 IterativeGrabCutDisplay 为一个 SegmentationCanvas，消除重复逻辑与显示切换
  2. 矩形自动分割 — 绘制矩形后 立即 执行 GC_INIT_WITH_RECT（3 次迭代），无需额外点击
  3. 上下文相关笔触 — 左键拖拽 = 前景笔触（红色叠加），Ctrl+左键拖拽 = 背景笔触（绿色叠加），每次释放自动运行 GC_INIT_WITH_MASK（2 次迭代）
  4. GMM 模型持久化 — bgdModel / fgdModel 在整个交互周期内保留，OpenCV 从上次 GMM 状态继续学习
  5. 结果即时可见 — 分割结果叠加显示在原始图像上（半透明蓝色前景），用户随时可看到当前 Mask 效果
  6. 任意步骤可往下走 — 矩形分割后的结果可直接"应用Mask"，涂抹修正后的结果也可以随时"应用Mask"，不需要先走完所有步骤

🧩 核心实现

新的 SegmentationCanvas 类

合并 InteractiveImageDisplay 和 IterativeGrabCutDisplay 的功能，新增 GrabCut 引擎集成：

class SegmentationCanvas(tk.Frame):
    """统一分割交互画布：矩形→自动GrabCut→涂抹修正"""

    def __init__(self, parent, ...):
        self.image = None           # RGB 源图像
        self.mask = None              # GrabCut mask (GC_BGD/GC_FGD/GC_PR_BGD/GC_PR_FGD)
        self.result_mask = None        # 二值结果 (0/255)
        self.bgd_model = np.zeros((1, 65), np.float64)
        self.fgd_model = np.zeros((1, 65), np.float64)
        self.has_init = False          # 是否已执行过首次分割
        self.mode = 'rect'            # 'rect' | 'fgd' | 'bgd' | 'view'

    def run_initial_rect(self, x1, y1, x2, y2):
        """矩形初始化 + 立即 GrabCut"""
        cv2.grabCut(self.image, self.mask, (x1, y1, x2-x1, y2-y1),
                     self.bgd_model, self.fgd_model, 3, cv2.GC_INIT_WITH_RECT)
        self.has_init = True
        self._update_result()

    def add_stroke(self, points, is_foreground=True):
        """添加笔触 + 自动迭代"""
        val = cv2.GC_FGD if is_foreground else cv2.GC_BGD
        for i in range(len(points)-1):
            cv2.line(self.mask, points[i], points[i+1], val, self.brush_width)
        cv2.grabCut(self.image, self.mask, None,
                     self.bgd_model, self.fgd_model, 2, cv2.GC_INIT_WITH_MASK)
        self._update_result()

    def get_result(self) -> np.ndarray:
        return np.where(
            (self.mask == cv2.GC_FGD) | (self.mask == cv2.GC_PR_FGD), 255, 0
        ).astype(np.uint8)

📖 OpenCV GrabCut API 参考

模式说明迭代次数
GC_INIT_WITH_RECT提供矩形 ROI，自动初始化前景/背景 GMM首次 3 次
GC_INIT_WITH_MASK提供标记 mask（FGD/BGD），结合已有 GMM 细化笔触后 2 次
mask 值常量含义
0GC_BGD确定背景（矩形外区域、用户背景笔触）
1GC_FGD确定前景（用户前景笔触）
2GC_PR_BGD可能背景（GMM 推测）
3GC_PR_FGD可能前景（GMM 推测/上轮结果）

关键约束： GC_INIT_WITH_MASK 要求 mask 必须 同时包含 GC_BGD(0) 和 GC_FGD(1) 的样本，否则 OpenCV 会因 GMM 缺少一类样本而断言失败。这就是当前代码中"只标记前景不标记背景"导致崩溃的原因。新设计中通过矩形初始化保证两类样本都存在。

# GrabCut 矩形初始化 + 笔触细化验证（可直接用 python 运行）
import cv2
import numpy as np

img = np.zeros((200, 300, 3), dtype=np.uint8)
img[40:160, 50:250] = (0, 200, 0)  # 绿色前景
img_bgr = cv2.cvtColor(img, cv2.COLOR_RGB2BGR)

mask = np.zeros(img.shape[:2], dtype=np.uint8)
bgd = np.zeros((1, 65), np.float64)
fgd = np.zeros((1, 65), np.float64)

# 第一步：矩形初始化
cv2.grabCut(img_bgr, mask, (30, 30, 240, 140), bgd, fgd, 3, cv2.GC_INIT_WITH_RECT)

# 第二步：背景笔触 + 迭代
mask[100:110, 30:270] = cv2.GC_BGD
cv2.grabCut(img_bgr, mask, None, bgd, fgd, 2, cv2.GC_INIT_WITH_MASK)

result = np.where((mask == cv2.GC_FGD) | (mask == cv2.GC_PR_FGD), 255, 0).astype(np.uint8)
assert result[50, 80] == 255, "前景应保留"
assert result[105, 80] == 0, "背景笔触应移除"
print("Segmentation test PASSED")

🎯 总结

本次优化将 6 步 7 按钮的分割流程精简为 3 步核心操作，核心变化：

  1. 两组件合一 — 消除 InteractiveImageDisplay 和 IterativeGrabCutDisplay 的重复代码与显示切换
  2. 矩形即分割 — 绘制矩形后自动执行 GrabCut，无需额外点击
  3. 笔触自动迭代 — 左键/左键+Ctrl 区分前/背景，每笔释放自动 GMM 迭代
  4. GMM 持久化 — bgdModel / fgdModel 在交互周期内保留，每次迭代从上次状态继续学习
  5. 任意步骤可用 — 矩形分割后的结果可直接"应用Mask"，笔触修正后的结果也可直接"应用Mask"

保留阈值/形态学等现有分割方法作为辅助功能，不影响已有代码的使用。
