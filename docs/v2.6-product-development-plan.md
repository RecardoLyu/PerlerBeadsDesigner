# 拼豆图纸设计器 v2.6 产品与开发计划

> 基于 v2.5.1 源码与现有双端功能整理
> 文档目的：统一产品范围、页面流程、数据结构、开发任务与验收口径
> 当前状态：开发中，未完成任务不代表已承诺排期

---

## 1. 版本定位

### 1.1 一句话目标

把“照片转换器 + 独立画板”升级为“从新建到拼制的完整作品工具”。

### 1.2 核心用户闭环

```text
新建／打开作品
  → 导入照片或空白绘制
  → 生成可编辑网格
  → 逐格微调
  → 保存与恢复作品
  → 导出效果预览／拼制 PNG
  → 按 BOM 备豆并实际拼制
```

### 1.3 目标用户

- **新手与休闲玩家**：希望默认设置就能做出颜色适中、尺寸可完成、导出后容易看懂的图纸。
- **有经验的拼豆创作者**：需要逐格编辑、控制品牌色、保存作品并获得可靠的大图纸输出。

v2.6 默认路径优先服务新手，高级能力保留但不阻塞主流程。

### 1.4 版本成功标准

1. 用户关闭并重新打开应用后，可以继续上次未完成的可编辑作品。
2. 照片生成结果无需重新转换，即可进入画板逐格编辑。
3. 新手不做高级参数设置，也能通过预设得到难度明确的图纸。
4. 用户可以导出带逐格色号、全局坐标和 BOM 的拼制 PNG；桌面可另存 BOM CSV。
5. 同一项目与同一输入在桌面端、安卓端具有一致的网格和 BOM。

## 2. 范围与优先级

### 2.1 v2.6 必须完成（Must）

| 编号 | 工作流 | 交付结果 |
|---|---|---|
| A | 作品项目化 | 新建、打开、保存、另存为、最近作品、自动保存、未保存保护 |
| B | 统一可编辑网格 | 照片转换结果直接进入画板编辑；转换与手绘共用网格、BOM、导出 |
| C | 双用途图纸输出 | 效果预览与拼制图纸分离；拼制图纸带逐格色号与坐标 |
| D | PNG 与清单 | 双端导出 PNG；桌面端可选同时导出 BOM CSV，移动端不提供 BOM 文件导出 |
| E | 新手预设与成本提示 | 新手易拼／平衡／高保真／自定义；生成前显示难度与成本预估 |
| F | 轻量神经分割 | 桌面优先适配 U²-Netp，支持 CPU、DirectML 与可选 CUDA；移动端只做负载评估与技术验证 |
| G | 双端一致性与质量门禁 | 统一项目格式、黄金样本、核心流程自动化测试接入 CI |

### 2.2 有余力再完成（Should）

- 导出成功后“打开文件／打开所在目录／系统分享”。
- 最近作品缩略图与按修改时间排序。
- 桌面端神经分割阈值预设与代表图集质量对比。
- 项目文件损坏时的可读错误与备份恢复。

### 2.3 本版本明确不做（Non-goals）

- 社区、账号、云同步和多人协作。
- 插件系统、批量转换。
- TIFF／SVG 等更多输出格式。
- 自定义任意矩形空白画板与多底板排版编辑器。
  - 注意：底层网格必须从本版本开始支持矩形，以承载照片转换结果；只是暂不开放自定义矩形新建入口。
- 品牌切换时自动重新映射全部颜色。
- 库存管理、采购包装换算。
- 移动端正式接入神经网络运行时；移动端是否进入后续版本由真机负载验收决定。
- 人像专用 matting、点／框提示大模型与更多分割网络的同时接入。
- 继续扩展皮肤、装饰性动效。

## 3. 产品信息架构与页面流程

## 3.1 新建与首页

不增加复杂门户，使用轻量启动页或首页抽屉即可。

```text
继续上次作品（有自动保存时）
最近作品（缩略图、名称、修改时间）
────────────────
从照片创建
创建空白画板
打开项目文件
```

规则：

- “从照片创建”和“创建空白画板”只是不同起点，不再对应两个孤立的数据模型。
- 新建空白画板仍默认 52×52，保留 104×104。
- 从照片创建时，先进入素材步骤；从空白创建时，直接进入编辑步骤。
- 有未保存修改时，新建、打开、清空、切换破坏性规格前必须提醒。

## 3.2 主界面任务步骤

统一为五个概念步骤，但允许返回修改，不做只能向前的强制向导。

| 步骤 | 用户任务 | 默认展示 | 高级设置 |
|---|---|---|---|
| 1. 素材 | 导入、裁剪、亮度／对比度、可选抠图 | 导入、常用调整、U²-Netp 抠图 | 计算后端、前景阈值、传统分割算法、形态学 |
| 2. 生成 | 选择预设、品牌、尺寸与颜色 | 四个预设、尺寸、成本预估、生成按钮 | 色差、抖动、ICM、细节保留 |
| 3. 编辑 | 逐格修正和手绘 | 画笔、橡皮、填充、色板、撤销重做 | 底图变换等 |
| 4. 导出 | 导出当前作品 | PNG、项目文件；桌面可选 BOM CSV | PNG 分辨率、标题 |
| 5. 拼制辅助 | 查看清单和图纸 | BOM、总豆数、颜色数 | 双端只读查看；BOM 文件导出入口仅桌面提供 |

“拼制辅助”不单独开发复杂模块，可作为导出前后的查看状态；若增加界面成本，则并入导出步骤。

### 3.3 桌面端布局

```text
顶部：作品名｜保存状态｜设置
左侧：当前任务步骤与参数
中间：画布（原图／Mask／效果预览／拼制图纸／编辑网格）
右侧或底部可收起区：BOM、作品成本、导出摘要
```

原则：

- 左侧只展开当前步骤，减少所有算法卡片同时出现。
- 画布模式按当前内容动态启用；没有 Mask 时，不展示可点击的 Mask／应用结果。
- 编辑网格与效果预览是同一数据的不同渲染，不是两份作品。
- 导出设置统一，不再让图像转换与画板分别维护一套不一致的选项。

### 3.4 安卓端布局

保持移动端单手操作，不机械复制桌面侧栏。

- 底部主导航建议为“素材／生成／编辑／导出”。
- 编辑时当前颜色、画笔、橡皮、撤销常驻紧凑工具栏。
- 高级参数继续使用底部 Sheet。
- 色板可展开，但当前色和换色入口始终可见。
- 触控目标至少 44×44，色号文字保证可读。
- 生成、导出、保存期间保留即时反馈，长任务不阻塞手势和页面切换。

## 4. 统一领域模型

## 4.1 核心原则

**可编辑网格是作品的唯一事实来源。**

原图、Mask、BOM、效果预览、拼制图纸和导出文件均围绕它组织：

```text
ProjectDocument
├── 源素材（可选）：原图、工作图、Mask、参考底图
├── 网格（必需）：宽、高、每格品牌色号或空值
├── 生成参数（可选）：预设、量化与分割配置
├── 编辑器状态：当前风格、底图变换等
└── 派生结果：BOM、统计、预览、导出（可重新计算，不作为权威数据）
```

要求：

- 网格支持矩形与空格，空格统一为 `null`。
- 色号必须结合品牌解释，品牌是项目数据的一部分。
- BOM 不手工维护，网格变化后统一重新统计。
- 转换后编辑只修改网格，不自动重新运行量化。
- 重新生成属于覆盖性操作，默认先保留当前版本副本或明确提醒。

## 4.2 `.pbd` 项目文件

采用 ZIP 容器，扩展名为 `.pbd`，便于双端读写和后续兼容。

```text
作品.pbd
├── manifest.json          # 元数据、尺寸、品牌、参数、资源索引
├── grid.json              # 可编辑网格，字符串色号或 null
├── assets/
│   ├── source.png         # 可选，无损源图
│   ├── working.png        # 可选，工作图
│   ├── mask.png           # 可选，单通道 Mask
│   └── reference.png      # 可选，参考底图
└── thumbnail.png          # 最近作品列表缩略图
```

`manifest.json` 建议字段：

```json
{
  "schemaVersion": 1,
  "projectId": "uuid",
  "name": "我的拼豆作品",
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601",
  "createdBy": "perler-beads-designer",
  "appVersion": "2.6.0",
  "origin": "conversion | blank",
  "canvas": {
    "width": 104,
    "height": 61,
    "brand": "mard"
  },
  "generation": {
    "preset": "balanced",
    "parameters": {}
  },
  "editor": {
    "beadStyle": "square",
    "referenceTransform": {}
  },
  "resources": {
    "grid": "grid.json",
    "source": "assets/source.png",
    "working": "assets/working.png",
    "mask": "assets/mask.png",
    "reference": "assets/reference.png",
    "thumbnail": "thumbnail.png"
  }
}
```

格式规则：

- 不保存设备绝对路径，项目可跨设备打开。
- 图像使用 PNG，避免重复保存造成质量损失。
- `schemaVersion` 用于未来迁移；未知高版本应提示升级，不静默清空。
- BOM、总豆数、预览缓存不写入权威状态，打开后重新计算。
- 撤销历史不进入 v1 项目格式，重启后从历史清空开始。
- 自动保存与用户显式保存分开记录，避免覆盖用户明确命名的文件。

## 4.3 保存与恢复策略

- 显式保存：写临时文件，校验成功后原子替换目标文件。
- 自动保存：编辑停止后防抖执行；生成、导入底图、清空等操作后立即排队保存。
- 启动恢复：检测到比显式文件更新的自动保存时，询问“恢复上次编辑”。
- 异常保护：保留最近一次有效自动保存，避免半截文件覆盖唯一副本。
- 安卓：最近草稿保存在应用文档目录；导入／导出项目使用系统文件选择或分享能力。
- 桌面：项目路径仅用于保存位置，不写入项目包内部。

## 5. 各工作流详细方案

## A. 作品项目化

### 用户可见功能

- 新建、打开、保存、另存为。
- 最近作品与继续上次编辑。
- 作品名和保存状态：已保存／未保存／保存中／保存失败。
- 自动保存与异常恢复。
- 破坏性操作确认。

### 技术任务

- 建立跨端一致的 `ProjectDocument` 概念模型和 schema v1。
- 桌面新增项目序列化、原子写入、最近项目元数据与原生文件对话框。
- 安卓新增项目仓库、应用文档目录、系统导入／导出。
- 把现有 `settings.json` 与项目数据分开：设置是偏好，不是作品。
- 将自动保存接入网格、Mask、生成参数和底图变化。

## B. 转换结果进入画板

### 用户流程

```text
生成图纸
  → 预览效果与成本
  → 点击“进入编辑”
  → 在相同网格上逐格修改
  → BOM 自动更新
  → 保存或导出
```

### 技术任务

- 让生成器输出品牌色号网格和 bead mask，而不只输出预览与 BOM。
- 桌面统一当前 generator 与 board 的状态所有权，避免 `board_to_generator()` 与生成器相互覆盖。
- 安卓统一 `patternProvider` 与 `boardProvider` 对项目网格的访问。
- 画板渲染支持非正方形网格。
- 保留源图和 Mask，使“返回重新生成”仍有完整上下文。
- 对手工编辑后的项目设置 `hasManualEdits`，重新生成前提示。

## C. 效果预览与拼制图纸分离

### 名称与用途

| 输出 | 用途 | 默认内容 |
|---|---|---|
| 效果预览 | 展示拼成后的观感、分享 | 真实豆子渲染，可不带逐格色号 |
| 拼制图纸 | 逐格对照实际制作 | 方格／符号、逐格色号、网格坐标、BOM |

规则：

- 新建项目的默认“拼制输出”使用带色号图纸。
- 真实风保留，但明确标记为效果预览，不把它作为默认拼制图纸。
- 对过长色号提供可读字号和必要时符号映射，不能裁切。
- 不只依靠颜色传达信息；色号和符号需在灰度显示时仍可辨认。

## D. PNG 输出与 BOM 清单

### 输出范围

- 桌面端与安卓端的图像转换、图纸画板均只导出 PNG 图纸。
- 桌面端提供“同时导出 BOM（CSV）”选项，默认不勾选；勾选后生成 `<作品名>.png` 与 `<作品名>_bom.csv`。
- 安卓端只保留 PNG 导出入口；BOM 可继续在界面和 PNG 图纸中查看，但不提供独立 BOM 文件导出。
- 图纸 PNG 保留逐格色号、全局坐标和 BOM 条；效果预览与拼制图纸继续共用同一权威网格。
- 导出前显示目标像素尺寸，避免大图纸在高倍缩放下造成内存峰值。
- Mask 空格与有豆格必须明确区分，导出结果与当前 BOM 一致。

桌面 BOM CSV 至少包含：

```text
brand,code,name,count,percentage
```

CSV 使用带 BOM 的 UTF-8 编码，按数量降序排列，确保常见表格软件可直接打开。

## E. 新手预设与成本提示

### 推荐预设

| 预设 | 建议初始策略 | 说明 |
|---|---|---|
| 新手易拼 | 宽约 52 豆、最多约 16 色、开启适度平滑 | 小作品、少颜色、低噪点 |
| 平衡 | 宽约 104 豆、最多约 32 色、适度细节与平滑 | 新用户默认 |
| 高保真 | 尺寸与颜色限制放宽 | 强调还原，明确提示制作成本更高 |
| 自定义 | 展开全部参数 | 保留当前高级能力 |

这些数值作为首轮默认值，需用样本图测试后定稿；不是算法硬限制。

### 成本卡片

生成前显示：

- 网格宽×高。
- 预计总豆数或上限。
- 目标颜色数／颜色上限。
- 预计 52×52 标准底板数量。
- 按品牌豆径估算的实物尺寸。
- 难度标签：简单／适中／复杂。

口径要求：

- 未实际生成前标注“预估”，颜色数不能伪装成精确值。
- 生成后更新为精确 BOM 统计。
- 有 Mask 时，豆数预估应扣除背景空格。
- 老用户已有默认设置不被强制覆盖；预设主要作用于新建项目。

## F. 轻量神经分割与移动端负载评估

### 桌面端首选方案

第一版采用 **U²-Netp FP32 ONNX，固定 320×320 输入**。它面向通用显著物体，比人像专用 MODNet、PP-Matting、PP-HumanSeg、RVM 更适合人物、玩具、手工作品等混合素材。上游公开权重约 4.7 MB，采用 Apache-2.0；运行时不需要 PyTorch。

- 模型来源与 SHA-256 记录在 `src/assets/models/README.md`，许可证随模型保留。
- 预处理：RGB、320×320、`[0,1]`、ImageNet mean/std，NCHW float32。
- 输出：取融合主输出，进行安全的 min-max 归一化、双线性还原尺寸，再按可调阈值生成 0／255 Mask。
- 显著性 Mask 不是精细 alpha matte；多主体、低对比、镂空与半透明边缘仍需 GrabCut、涂抹和形态学兜底。
- 不同期引入人像专用网络或点／框提示大模型，先用项目代表图集验证 U²-Netp 的适用范围。

### CPU／GPU 后端与发行

- Windows 标准包采用 `onnxruntime-directml`，提供 DirectML 和 CPU；自动模式优先可用 GPU，用户可强制 CPU。
- NVIDIA CUDA 作为独立可选构建，使用匹配 CUDA／cuDNN 的 `onnxruntime-gpu`，不与 DirectML 包混装。
- macOS／Linux 使用普通 `onnxruntime` CPU 包。
- 界面提供“自动／CPU／DirectML／CUDA”选择，并显示模型与实际可用后端状态；显式选择不可用后端时给出明确错误。
- 会话按模型和后端缓存，避免每次分割重复加载；自动模式 GPU 初始化失败时回退 CPU。
- 发布包只带 ONNX、ONNX Runtime 和许可证，不带 PyTorch；在干净 Windows 环境验证原生 DLL 收集。

### 本轮桌面验证记录

在同一 1280×720 合成图上做了功能烟雾验证，CPU 与 DirectML 得到一致的前景像素数，Mask 尺寸和类型正确。单次结果仅证明本机链路可用，不作为通用性能承诺：

| 后端 | 冷启动（含建会话） | 预热后一次 | 验证范围 |
|---|---:|---:|---|
| CPU，ONNX Runtime 1.31.0 | 约 373 ms | 约 93 ms | 本机实测 |
| DirectML，ONNX Runtime DirectML 1.24.4 | 约 1603 ms | 约 18 ms | 本机实测 |
| CUDA | 待测 | 待测 | 当前无匹配硬件／运行时，不能视为已验收 |

后续应使用代表图集记录冷启动、预热 P50／P95、内存和分割质量，不能用上述单次耗时替代发布基准。

### 移动端是否接入

本版本不正式接入移动端神经网络。桌面效果、数值一致性和打包基线建立前，不同时引入 Flutter FFI、原生运行时裁剪与热耗问题。后续技术验证优先复用同一 ONNX，采用 ONNX Runtime Mobile CPU／XNNPACK；NNAPI 仅在 CPU／XNNPACK 不达标时验证。TFLite 需要额外转换和数值验证，不作为首选。

移动端进入正式版本前，至少在低端和中端 Android 真机达到以下**建议门槛**（均为验收目标，不是当前实测结果）：

| 项目 | 建议准入门槛 |
|---|---|
| 包体 | arm64 单 ABI APK 增量不超过 20 MB，同时记录 AAB 下载增量 |
| 内存 | 12 MP 输入完整流程峰值增量 RSS 不超过 150 MB；连续 20 次无 OOM 或持续增长 |
| 速度 | 中端预热后 P95 不超过 1.0 s，低端不超过 2.0 s，包含预处理与 Mask 还原 |
| 冷启动 | 首次建会话与推理不超过 2.5 s，或有清晰进度和取消能力 |
| 一致性 | 相同预处理与阈值下，移动和桌面的二值 Mask IoU 不低于 0.99 |
| 热稳定 | 连续 10 分钟无热警告、崩溃；后 5 次 P95 相对预热基线恶化不超过 20% |
| UI | 推理在 Isolate／原生工作线程执行，无 ANR，页面交互不被阻塞 |

未达标时继续保留现有移动端传统分割，不以“桌面能运行”为理由强制上线移动端。

| 顺序 | 任务 | 桌面端 | 安卓端 | 测试／共同交付 |

| 9 | 双端 QA | 小窗口、键盘、保存反馈 | 触控、后台恢复、性能 | CI 测试、真实 PNG 检查与真机验收 |

### 6.1 建议模块边界

桌面端可逐步拆分为：

```text
src/core/project/          # 项目文档、schema、迁移
src/core/grid/             # 网格操作与 BOM 派生
src/core/export/           # 效果图、拼制 PNG、桌面 BOM CSV
src/utils/                 # 传统分割与 ONNX 神经分割
src/webapp/                # 路由、会话和原生交互
```

安卓端可逐步拆分为：

```text
lib/models/                # ProjectDocument、PatternGrid
lib/services/project/      # 项目读写、自动保存、最近项目
lib/services/export/       # 仅 PNG；不提供 BOM 文件导出
lib/ui/                    # 只负责展示与交互
```

不要求一次性大规模改名，但新增能力不得继续把项目读写、算法和 UI 全部塞进单一状态文件。

## 7. 测试与验收标准

## 7.1 作品保存验收

- 新建空白画板并绘制，保存后关闭，再打开，网格、品牌、尺寸完全一致。
- 照片项目重新打开后，源图、Mask、网格和生成参数均恢复。
- 修改后未显式保存，强制结束应用，重启可恢复最近草稿。
- 保存失败有明确提示，不能把旧文件破坏，也不能错误显示“已保存”。
- 含中文、空格、特殊字符的作品名可正常保存与打开。
- 不兼容的高版本项目不会被静默清空。

## 7.2 转换与编辑验收

- 照片生成后点击“进入编辑”，不需要重新量化。
- 修改一颗豆后，只该格与 BOM 统计变化。
- 编辑后效果预览、拼制图纸和 PNG 使用同一网格；桌面勾选 BOM 时，CSV 也由同一网格生成。
- 非正方形图纸可编辑、缩放、保存和导出。
- 手工编辑后重新生成有覆盖提醒，取消不会丢失修改。

## 7.3 PNG 与 BOM 验收

- 拼制 PNG 中每颗有豆格都能通过色号或符号映射到 BOM。
- 真实风仅作为效果预览时，用户不会误以为其包含逐格编号。
- 104×61、208×156 等矩形图纸导出后行列完整、全局坐标正确，色号不裁切。
- 桌面勾选 BOM 后同时得到 PNG 与 CSV；不勾选时只得到 PNG。
- CSV 的品牌、色号、名称、数量、百分比与当前网格一致，中文可被常见表格软件正确读取。
- 安卓转换和画板均只有 PNG 导出入口，不出现独立 BOM 文件导出按钮。
- 双端 PNG 均可被常见图片查看器打开，大图纸导出不会导致界面假死或明显内存失控。

## 7.4 预设与成本验收

- 新用户使用默认“平衡”预设，无需理解 ICM／色差算法即可完成生成。
- 新手预设确实限制颜色和尺寸，高保真预设不会被套用同样限制。
- 生成前预估值有明确标识，生成后精确值与 BOM 一致。
- Artkal C-2.6mm 与 5mm 品牌的实物尺寸计算不混用。
- 老用户自定义默认参数不会被版本升级静默重置。

## 7.5 双端一致性黄金样本

至少覆盖：

1. 52×52 空白手绘与空格。
2. 104×61 矩形照片转换。
3. 带 Mask 的前景图纸。
4. 多品牌与长色号。
5. 16 色和不限色两档。
6. 208×156 大尺寸 PNG。
7. 中文项目名与跨端项目打开。

同一输入下：

- 网格尺寸、每格色号、空值和 BOM 必须一致。
- 渲染允许存在抗锯齿像素差，但布局、文字内容和网格语义必须一致。

## 7.6 神经分割验收

- 官方来源、许可证、模型哈希和输入输出契约齐全，模型随桌面包可用。
- CPU 与 DirectML 均完成真实模型推理；CUDA 在匹配硬件上单独验收，不用模拟测试代替。
- 显式后端不可用时提示清晰；自动模式 GPU 初始化失败可回退 CPU，不阻断传统分割。
- 固定输入下各后端 Mask 数值差异在项目实测容差内，常量输出不会产生 NaN。
- 记录代表图集的质量、冷启动、预热 P95 和内存；移动端未过准入门槛前不出现神经分割入口。

## 8. CI 与发布门槛

### 8.1 CI 必须执行

桌面：

```text
安装依赖 → pytest → 构建 → 启动烟雾测试 → 核心 API 回归
```

安卓：

```text
flutter pub get → flutter analyze → flutter test → release 构建
```

增加跨端样本测试，避免“算法各自移植后逐渐产生不同结果”。

### 8.2 发布前人工验收

- Windows 与安卓各完成一次完整闭环。
- 打开桌面与安卓导出的大尺寸 PNG，核对色号、坐标、清晰度和 BOM。
- 桌面分别验证仅 PNG、PNG＋BOM CSV；安卓确认没有 BOM 文件导出入口。
- 安卓验证切后台、杀进程、存储空间不足和保存失败。
- 检查小窗口、亮暗主题、触控尺寸、键盘焦点和错误提示。
- 验证从 v2.5.1 升级后设置保留，旧版本没有项目文件时提供清晰的新入口。
- 在干净 Windows 环境验证模型随包加载、DirectML／CPU 切换和 GPU 失败回退。

### 8.3 不可发布的情况

- 存在作品丢失或错误提示已保存的问题。
- 转换、画板、导出使用不同网格或 BOM。
- 大图纸 PNG 漏格、坐标错误或桌面 CSV 与 BOM 不一致。
- 移动端出现计划外的 BOM 文件导出入口。
- 桌面／安卓核心自动化测试未运行或失败。
- 默认拼制图纸无法逐格对应色号。
- 桌面包缺少模型、许可证或可用 CPU 后端，导致默认神经分割不可用。

## 10. 主要风险与处理

| 风险 | 处理策略 |
|---|---|
| 同时改状态和 UI，回归范围过大 | 先统一模型，UI 分阶段接入；保留旧流程适配层 |
| 自动保存频繁写大图导致卡顿 | 网格先行防抖保存，图像资源按内容变化保存，避免每次重复写入 |
| 项目文件过大 | ZIP 无损压缩、缩略图独立、派生预览不入包 |
| 手工编辑被重新生成覆盖 | 标记手工修改，二次确认并保留副本 |
| 双端算法继续漂移 | 固定输入、参数和网格结果的黄金测试 |
| 大尺寸 PNG 内存过高 | 导出前显示像素尺寸，限制异常倍率并采用分块渲染评估 |
| 神经分割误抠或多主体不符合预期 | 明确“主要显著物体”语义，保留阈值、GrabCut、涂抹与传统算法 |
| GPU 运行时或驱动不兼容 | CPU 保底、后端状态可见、自动回退、分构建隔离运行时 |
| 移动端包体与热耗失控 | 本版不正式接入；先做裁剪运行时 spike，达到真机准入门槛再排期 |
| v2.6 范围膨胀 | Non-goals 不进入本版；Should 项不得阻塞 Must 项发布 |

## 11. 评审时需要确认的产品决策

1. 新用户默认预设采用“平衡”还是更保守的“新手易拼”。
2. 拼制图纸采用“始终逐格色号”，还是允许用户在色号与符号映射之间选择。
3. 最近作品是否只做本机列表；本计划默认不做云同步。
4. 自动保存恢复默认询问还是直接恢复；本计划建议询问，避免覆盖用户主动放弃的旧草稿。
5. 高保真预设是否保持颜色不限；本计划建议保留，但必须显示复杂度和成本提示。

## 结论

v2.6 的重点不是无边界堆叠算法，而是建立三个长期基础：

1. **统一、可编辑、可移植的作品模型。**
2. **面向新手可理解、面向熟手可控制的创作流程。**
3. **以 PNG 和桌面 BOM 清单为核心的可拼制输出体系。**

完成这些之后，画板效率、库存管理、多底板拼接和分享能力才有稳定的扩展基础。
